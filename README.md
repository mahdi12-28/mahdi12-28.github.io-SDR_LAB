# دفتر نیمسال آزمایشگاه رادیو نرم‌افزار

برای شروع سریع، `START-HERE.md` را بخوانید. سایت از HTML/CSS دست‌نویس و JavaScript سبک استفاده می‌کند و مستقیم روی GitHub Pages قابل نمایش است. فایل‌های وب ساخته‌شده در بسته موجودند؛ بازدیدکننده به نصب ابزار یا ورود به حساب نیاز ندارد.

## محتوای آزمایش صفر

گزارش HTML و PDF از یک منبع مشترک ساخته می‌شوند. متن شامل هدف، مبانی، روش‌های دستورکار، تنظیمات قابل‌خواندن، خروجی ping و پایتون، وضعیت هر مسیر، عیب‌یابی ثبت‌شده، ایمنی، فایل‌های همراه و مراجع است. ۱۷ تصویر اصلی بدون تغییر محتوای آن‌ها نگه داشته شده‌اند.

گزارش، **ثبت مدارک موجود** است. خروجی‌های موجودنبوده، مسیر Ubuntu، دادهٔ خام و فلوگراف اصلی به‌صورت انجام‌شده یا تأییدشده معرفی نشده‌اند. تحلیل، تفسیر داده و نتیجه‌گیری اختصاصی اعضا در ورودی نبود و به آن‌ها نسبت داده نشده است. آیین‌نامهٔ ارسالی در بند ۷-۵، این بخش‌ها را بر عهدهٔ اعضای گروه می‌گذارد. اعلام استفاده از ChatGPT در گزارش وب و PDF موجود است.

## یک محل برای مشخصات اعضا

تنها فرم خالی گزارش، چهار مقدار نام و شمارهٔ دانشجویی در `content/team.json` است. ورود تعاملی:

```bash
python tools/update_members.py
```

یا در ویندوز `UPDATE-MEMBERS.bat` را اجرا کنید. پس از ویرایش مستقیم JSON، فرمان زیر تمام خروجی‌ها را هماهنگ می‌کند:

```bash
python tools/refresh.py
```

این فرمان ابتدا HTML و TEX، سپس PDF و در پایان ZIP منبع را می‌سازد. Python 3.9+ و XeLaTeX/BibTeX از توزیع کامل TeX Live یا MiKTeX لازم‌اند. برای فقط HTML و منبع TEX:

```bash
python tools/build.py
```

برای ساخت فقط یک PDF:

```bash
python tools/build_pdf.py --lab lab00 --kind post
```

برای بسته‌بندی منابع پس از بازسازی:

```bash
python tools/package.py
```

فایل ZIP منبع، `report.tex` و `references.bib` را در ریشه دارد و قلم و تصاویر را در `assets` نگه می‌دارد. آن را می‌توان در محیط دارای XeLaTeX، از جمله Overleaf، کامپایل کرد. پس از تغییر نام‌ها یا متن، PDF قدیمی خودبه‌خود تغییر نمی‌کند؛ PDF تازه را بسازید یا نسخهٔ کامپایل‌شده را جایگزین کنید.

## ساخت آزمایش بعدی

```bash
python tools/new_lab.py 1 --title "عنوان واقعی آزمایش اول"
```

ابزار، ورودی فهرست و دو فایل منبع مستقل برای پیش‌گزارش و گزارش می‌سازد. فایل‌های موجود را بازنویسی نمی‌کند. هر دو گزارش در ابتدا `publish: false` هستند و از صفحهٔ اصلی لینک ندارند. اگر پیش‌گزارش آماده شد، فقط مقدار `pre.publish` را تغییر دهید؛ لازم نیست گزارش پس از جلسه هم آماده باشد.

۱. متن پیش‌گزارش را در `content/lab01/pre.json` و متن گزارش را در `content/lab01/post.json` بنویسید.
۲. تصویرها، دادهٔ خام و کدهای واقعی را در پوشه‌های همان آزمایش قرار دهید.
۳. در `content/experiments.json`، تاریخ واقعی جلسه، وضعیت و تاریخ تحویل هر نوع گزارش را مستقل ثبت کنید.
۴. در زمان مناسب برای گنجاندن آن در خروجی، `publish` همان گزارش را `true` کنید و `python tools/refresh.py` را اجرا کنید.
۵. فهرست صفحهٔ اصلی و صفحات مربوط خودکار ساخته می‌شوند. لینک رفت‌وبرگشت بین پیش‌گزارش و گزارش فقط وقتی هر دو وجود دارند نمایش داده می‌شود.

`publish` فقط کنترل ساخت فایل HTML است؛ قفل امنیتی یا زمان‌بندی انتشار اینترنتی نیست. حتی فایل منبع و دادهٔ گزارش نباید قبل از مهلت در مخزن عمومی قرار گیرد. مخزن را تا زمان مجاز محلی یا خصوصی نگه دارید و Pages را زودتر فعال نکنید.

## نوشتن محتوا بدون دست‌زدن به HTML

هر فایل گزارش یک آرایهٔ `sections` دارد. هر بخش دارای `id` یکتا، `title` و آرایهٔ `blocks` است. مثال:

```json
{
  "id": "method",
  "title": "روش اجرا",
  "blocks": [
    {"type": "paragraph", "text": "متن یک پاراگراف با عبارت `Python` درون آن."},
    {"type": "table", "headers": ["پارامتر", "مقدار"], "rows": [["Gain", "20 dB"]], "caption": "تنظیمات ثبت‌شده", "label": "tab:lab01-gain"},
    {"type": "figure", "path": "assets/lab01/setup.png", "caption": "چیدمان واقعی آزمایش", "label": "fig:lab01-setup"}
  ]
}
```

بلوک‌های پشتیبانی‌شده عبارت‌اند از `paragraph`، `bullets`، `code`، `equation`، `table`، `figure`، `downloads`، `comments` و `references`. بلوک `gallery` مخصوص آرشیو ۱۷ تصویر آزمایش صفر است. نمونه‌های کامل در `content/templates/block-examples.json` قرار دارند و در فهرست گزارش‌ها منتشر نمی‌شوند.

- برای نمایش درست عبارت انگلیسی در متن فارسی، آن را بین دو علامت backtick قرار دهید.
- فرمول در `latex` بلوک `equation` نوشته می‌شود؛ از تصویر فرمول استفاده نکنید.
- هر شکل و جدول باید عنوان و `label` یکتا داشته باشد. موتور ساخت، شماره و ارجاع آن را در PDF ایجاد می‌کند.
- بخش فایل‌ها باید `id: "downloads"` داشته باشد تا دکمهٔ بالای صفحه به آن برسد.
- فایل‌های اضافه را در آرایهٔ `attachments` ثبت کنید؛ هر مورد `title`، `path` و `description` دارد.
- برای مراجع، ورودی‌های BibTeX را در `latex/references.bib` اضافه و کلیدهایشان را در `bib_keys` همان گزارش وارد کنید. فهرست خوانای وب را نیز در آرایهٔ `references` همان گزارش بنویسید. در گزارش صفر، مراجع از قبل درج شده‌اند.
- فایل‌های HTML و TEX خروجی‌اند؛ تغییر مستقیم آن‌ها در بازسازی بعدی از بین می‌رود. منبع JSON را تغییر دهید.

## کامنت واقعی برای داوری هر گزارش

بدون نام مخزن و شناسه‌های واقعی GitHub، اتصال کامنت قابل فعال‌شدن نیست. فرم نمایشی بدون ذخیره‌سازی در سایت قرار داده نشده است.

۱. در مخزن عمومی تیم، GitHub Discussions را فعال و برنامهٔ giscus را برای همان مخزن نصب کنید.
۲. در [پیکربندی رسمی giscus](https://giscus.app/) نام مخزن و دستهٔ کامنت را انتخاب کنید.
۳. چهار مقدار `repo`، `repoId`، `category` و `categoryId` را از کد رسمی در بخش `giscus` فایل `content/site.json` وارد کنید. این‌ها شناسه‌های عمومی‌اند، نه رمز یا توکن.
۴. `python tools/build.py` را اجرا کنید.
۵. پس از انتشار در زمان مجاز، نمایش و ثبت یک کامنت واقعی را بررسی کنید.

هر صفحه کلید ثابتی مانند `lab01-pre` یا `lab01-post` دارد؛ بنابراین کامنت‌های آزمایش‌ها و پیش‌گزارش‌ها با هم مخلوط نمی‌شوند. خواندن گزارش نیازمند ورود نیست؛ نوشتن کامنت با احراز هویت GitHub انجام می‌شود. طبق آیین‌نامه، گروه میزبان نباید کامنت‌های داوری را حذف یا ویرایش کند.

## انتشار در GitHub Pages

محتویات پوشهٔ سایت را در ریشهٔ مخزن قرار دهید؛ `index.html` و `.nojekyll` باید در ریشه باشند. در زمان مجاز مطابق آیین‌نامه:

۱. `Settings → Pages → Build and deployment` را باز کنید.
۲. `Deploy from a branch`، شاخهٔ `main` و پوشهٔ `/(root)` را انتخاب و ذخیره کنید.
۳. نشانی اعلام‌شده توسط GitHub را باز کنید و گزارش، PDF، منبع، تصویرها و کامنت‌ها را بررسی کنید.
۴. نشانی سایت و زمان واقعی تحویل را طبق روند درس در فرم مربوط ثبت کنید. وضعیت در سایت را به‌جای ثبت در فرم درس تلقی نکنید.

آیین‌نامهٔ ارسالی، انتشار گزارش را فقط در پایان مهلت همان گزارش مجاز می‌داند. این بسته انتشار یا زمان‌بندی اینترنتی خودکار ندارد. پس از ثبت تحویل نهایی نیز طبق آیین‌نامه خروجی گزارش نباید تغییر کند.

## حدود بررسی و تکمیل الزامات درس

ساخت PDF، منابع، ارجاع‌ها، مقصد لینک‌ها، هویت تصاویر و ساخت مسیر یک آزمایش بعدی بررسی شده‌اند. ابزار کامنت به مخزن شما وصل نیست و اتصال به دستگاه واقعی در این محیط انجام نشده است. زیرساخت پیش‌نمایش مرورگر در دسترس نبود؛ نمایش موبایل و دسکتاپ و بارگذاری MathJax/giscus را در مرورگر خودتان بررسی کنید.

بزرگ‌نمایی تصویر و فیلتر آرشیو موجودند، اما این‌ها به‌جای نمودار داده‌محور، صوت دمدولاسیون یا صورت‌فلکی تعاملیِ خواسته‌شده برای طول نیمسال معرفی نشده‌اند. آن بخش باید در آزمایش مناسب و با دادهٔ واقعی اضافه شود.

فونت و تصاویر محلی‌اند؛ MathJax و giscus به دسترسی اینترنت نیاز دارند. کدهای دریافت، قالب آموزشی‌اند و آزمون سخت‌افزاری نشده‌اند. در سایت، عدد ساختگی برای توان، SNR، سریال، تاریخ جلسه یا امضای دستیار درج نشده است.
