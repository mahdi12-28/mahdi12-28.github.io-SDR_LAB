# سایت گزارش آزمایش صفر — راهنمای شروع

این بسته یک سایت ایستای فارسی و راست‌به‌چپ برای GitHub Pages است. HTML/CSS دست‌نویس، صفحهٔ اصلی، گزارش HTML، تمام ۱۷ تصویر اصلی، پیش‌نویس PDF تولیدشده با LaTeX، منبع TEX و BibTeX و قالب کد دریافت در آن قرار دارد. برای نمایش سایت به npm یا نصب وابستگی نیاز ندارید. `index.html` را باز کنید.

**این نسخه پیش‌نویس است و برای تحویل نهایی کامل نیست.** نام و تاریخ ساختگی وارد نشده و نبود مدرک به‌معنای انجام‌نشدن آزمایش فرض نشده است.

## ۱. تکمیل محتوا

فایل `content/report.json` منبع اطلاعات مشترک سایت و گزارش LaTeX است. آن را با ویرایشگر متن باز کنید و این فیلدها را تکمیل کنید:

- `team_name` و `team_id`: نام و شناسهٔ تیم؛ نام بسته و فایل‌ها را هم با نام تیم هماهنگ کنید.
- `members`: نام دو عضو و شمارهٔ دانشجویی آن‌ها.
- `session_date` و `submission_date`: تاریخ واقعی جلسه و تحویل؛ تاریخ فایل عکس جای آن‌ها نیست.
- نسخه‌ها، سریال، سفت‌افزار، بازهٔ فعال و تنظیم IPv4 با مدارک واقعی.
- `analysis`، `conclusion`، `troubleshooting` و `ubuntu`: نوشتهٔ خود اعضای تیم؛ برای چند پاراگراف در JSON از `\n\n` استفاده کنید.
- `status`: فقط پس از تکمیل واقعی مدارک تغییر دهید. برنامه هیچ وضعیت «تحویل‌شده» یا امضایی را خودکار ثبت نمی‌کند.

آیین‌نامه در بند ۷-۵، استفاده از AI را برای قالب و ویرایش نگارشی مجاز می‌داند و تولید تحلیل، نتیجه‌گیری و تفسیر داده را مجاز نمی‌داند. به همین دلیل این بخش‌ها نوشته نشده‌اند. اعلام استفاده از ChatGPT در پایان هر دو نسخه وجود دارد؛ پس از ویرایش، آن را با استفادهٔ واقعی خود هماهنگ کنید.

سپس با Python 3.9 یا جدیدتر اجرا کنید:

```bash
python3 tools/build.py
bash tools/build-pdf.sh
python3 tools/package.py
```

برای ساخت PDF به توزیع کامل TeX Live یا MiKTeX دارای XeLaTeX، fontspec، geometry، graphicx، amsmath، xcolor، hyperref، fancyhdr و natbib، به‌علاوهٔ BibTeX نیاز است. قلم در بسته موجود است. جهت فارسی با امکانات بومی XeTeX تعریف شده است. PDF داخل `downloads` واقعاً با LaTeX تولید شده؛ چاپ مرورگر جایگزین آن نیست.

هر بار پس از تغییر JSON، هر سه فرمان را اجرا کنید تا HTML، PDF و ZIP منبع هماهنگ بمانند. برای تغییر ساختار و اضافه‌کردن لینک داده، `tools/build.py` را ویرایش کنید؛ فایل‌های HTML خروجی را مستقیم ویرایش نکنید، چون بازسازی آن‌ها را بازنویسی می‌کند.

## ۲. مدارک لازم پیش از تحویل

- [ ] نام تیم، اعضا، تاریخ جلسه و تاریخ تحویل.
- [ ] خروجی `info(rx)`، سریال و سفت‌افزار؛ نسخهٔ MATLAB و بازهٔ فعال.
- [ ] تصویر تنظیم IPv4 کارت شبکه.
- [ ] فایل اصلی `.grc` و پارامترهای واقعی فلوگراف.
- [ ] نسخهٔ pyadi-iio و کد اصلی پایتون و MATLAB جلسه.
- [ ] مدارک مسیر اوبونتو: نسخه‌ها، `iio_info`، GRC و ابزار اضافی.
- [ ] پاسخ خود تیم به معیار مشاهدهٔ سیگنال در هر مسیر.
- [ ] توضیح تیم دربارهٔ تنظیمات SDR++ و SDRangel در تصاویر یا افزودن تصاویر آزمون اصلاح‌شده. در بعضی تصاویر ۹۶ یا ۹۰ یا ۹۲۴ مگاهرتز، بهرهٔ ۴۵ دسی‌بل و برچسب USB دیده می‌شود؛ مقادیر خواسته‌شدهٔ دستورکار ۹۴۵ مگاهرتز، مسیر LAN و بهرهٔ دستی حداکثر ۳۰ دسی‌بل با آنتن هستند. تنظیمات واقعی را پنهان نکنید.
- [ ] دادهٔ خام I/Q و فراداده؛ نمودارهای علمی ترجیحاً برداری. اسکرین‌شات‌ها فقط مدرک رابط نرم‌افزار هستند.
- [ ] تحلیل، عیب‌یابی و جمع‌بندی نوشته‌شده توسط اعضای تیم.
- [ ] تأیید و امضای واقعی دستیار برای چک‌لیست تحویل، بدون جعل یا جایگزینی آن.
- [ ] اتصال giscus و آزمون ثبت یک کامنت واقعی پس از زمان مجاز انتشار.
- [ ] برای الزام تعامل در طول نیمسال، یک نمودار قابل بزرگ‌نمایی بر پایهٔ دادهٔ خام، صوت دمدولاسیون یا صورت‌فلکی تعاملی اضافه کنید. بزرگ‌نمایی تصاویر این نسخه را به‌جای نمودار داده‌محور معرفی نکنید.

فایل داده یا GRC ساختگی در این بسته وجود ندارد. پوشه‌های `data` و `flowgraphs` راهنمای افزودن فایل واقعی دارند. کدهای پوشهٔ `code` بازنویسی آموزشی دستورکارند، نه کد اصلی جلسه، و اتصال سخت‌افزاری آن‌ها اینجا آزموده نشده است.

## ۳. فعال‌کردن داوری همتا با giscus

این قسمت تا زمانی که مخزن خودتان را مشخص نکنید فعال نیست؛ کامنت نمایشی یا فرم بدون ذخیره‌سازی در سایت وجود ندارد.

۱. در مخزن GitHub تیم، Discussions را فعال کنید و برنامهٔ giscus را برای همان مخزن نصب کنید.
۲. در [پیکربندی رسمی giscus](https://giscus.app/)، نام مخزن عمومی و دستهٔ کامنت‌ها را انتخاب کنید.
۳. چهار مقدار `repo`، `repoId`، `category` و `categoryId` را از کد رسمی در فیلد `giscus` فایل `content/report.json` قرار دهید؛ این شناسه‌ها عمومی‌اند و توکن یا رمز نیستند.
۴. `python3 tools/build.py` را دوباره اجرا کنید. نگاشت هر گزارش با کلید ثابت `sdr-lab00-post-report` انجام می‌شود.
۵. در سایت منتشرشده، نمایش و ذخیرهٔ کامنت را با GitHub بررسی کنید. نوشتن کامنت به ورود GitHub نیاز دارد؛ خود گزارش عمومی و بدون ورود قابل‌خواندن است. برای گزارش‌های بعدی کلید نگاشت را عوض کنید تا کامنت‌ها مخلوط نشوند.

طبق بند ۵-۲ آیین‌نامه، تیم میزبان حق حذف یا ویرایش کامنت‌های داوری را ندارد. سایت دکمه‌ای برای این کار ندارد، اما رعایت این قاعده در GitHub نیز مسئولیت تیم است.

## ۴. انتشار در GitHub Pages، در زمان مجاز درس

**طبق بند ۵-۲ آیین‌نامه، فایل گزارش فقط در پایان مهلت همان گزارش باید منتشر شود.** پیش از آن نسخه را محلی یا در مخزن خصوصی نگه دارید و Pages را فعال نکنید. خصوصی‌بودن مخزن به‌تنهایی تضمین خصوصی‌بودن Pages نیست. این بسته هیچ انتشار یا زمان‌بندی خودکاری ندارد.

۱. محتویات پوشهٔ `sdr-lab0-site` را در ریشهٔ مخزن بگذارید؛ `index.html` باید در ریشه باشد. فایل `.nojekyll` را هم نگه دارید.
۲. در زمان مجاز انتشار، از `Settings → Pages → Build and deployment`، گزینهٔ `Deploy from a branch` را انتخاب کنید؛ شاخهٔ `main` و پوشهٔ `/(root)` را مشخص و ذخیره کنید.
۳. نشانی اعلام‌شده توسط GitHub را باز کنید؛ صفحهٔ گزارش، PDF، منبع LaTeX، تصاویر و کامنت‌ها را آزمایش کنید.
۴. نشانی سایت را طبق مهلت ثبت نشانی در فرم درس ثبت کنید. بعد از تحویل گزارش، زمان تحویل را هم در فرم درس وارد کنید؛ طبق آیین‌نامه، خروجی پس از ثبت زمان تحویل نباید تغییر کند.

برای پیش‌نمایش محلی، بازکردن `index.html` کافی است؛ برای آزمودن ابزارهای اینترنتی می‌توانید از یک سرور محلی استفاده کنید:

```bash
python3 -m http.server 8000
```

سپس `http://localhost:8000` را باز کنید. قلم، استایل و تصاویر محلی‌اند؛ MathJax و giscus به اینترنت نیاز دارند. بارگذاری موفق آن دو در شبکهٔ خودتان باید بررسی شود.

## بررسی انجام‌شده و محدودیت‌ها

منابع HTML/JavaScript، مقصد لینک‌های داخلی، کامل‌بودن آرشیو تصاویر و ساخت PDF بررسی شده‌اند. اتصال به دستگاه، اجرای MATLAB/GNU Radio و ذخیرهٔ کامنت در مخزن تیم آزموده نشده‌اند. زیرساخت پیش‌نمایش مرورگر این محیط در دسترس نبود؛ نمایش دسکتاپ و موبایل، بارگذاری MathJax و giscus را در مرورگر خودتان پس از راه‌اندازی بررسی کنید.
